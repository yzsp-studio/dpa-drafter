## 🇨🇳 中文

面向中国数据合规的律师型起草助手，先识别交易结构与数据处理关系，再分析法律规则适用与责任归属，最后输出结构完整、责任清晰、可签署、可落地的 DPA 或相关数据协议。它区分数据委托处理、数据对外提供与独立处理者之间的共享、数据共同处理，以及主协议项下的数据附属安排；在最小必要信息收集完成前，不会宣布协议类型，也不把初步判断当既定结论。三方协议会拆成多组双边关系分别起草，标准 DPA 建议 3000-6000 字，默认输出中文，也能对已有草稿提出修改建议并给出修订版，最终可生成 Word 文档。

- 三方协议拆成多组双边关系分别起草
- 模板只作参考，按双方角色与实际风险点选择性使用
- 终审校验后格式化输出 Word，标准 DPA 约 3000-6000 字

## 🇬🇧 English

A lawyer-style drafting assistant for Chinese data compliance: it identifies the transaction structure and the data-processing relationship, analyses which rules apply and where liability sits, then produces a complete, clearly allocated, signable and workable DPA or related data agreement. It distinguishes entrusted processing, provision to a separate controller, sharing between independent controllers, joint processing and data annexes under a master agreement, and refuses to announce the agreement type before minimal necessary facts are collected. Tripartite deals are split into bilateral pairs and drafted separately; a standard DPA runs 3,000-6,000 Chinese characters by default, output is Chinese-first, and an existing draft can be reviewed and returned as a revised version. Word output is supported.

### ✨ What it does

- Business context and data flows in → a signable DPA or related data agreement out
- Collects minimal necessary facts before naming the agreement type, avoiding premature classification
- Separates entrusted processing, provision to another controller, joint processing and mixed or annex structures
- Splits tripartite agreements into bilateral pairs and drafts each one separately
- Uses templates only as reference, selecting clauses by actual roles and risk points
- Runs a final review pass, then outputs formatted Word; a standard DPA runs about 3,000-6,000 characters
